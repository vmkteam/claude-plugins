# Changelog

## 1.3.0 — 2026-10-16

Опыт перестройки hubsrv: код пришлось переложить по слоям, потому что `/gold-arch`, `/colgen` и `/cron` не загружались — их описания не совпадали со словами задачи («воркер», «MCP», «цикл»), а спека и соседние сервисы диктовали устаревшую структуру.

### Изменения поведения

- **Описания /gold-arch, /colgen, /cron, /mfd** — триггеры по словам задачи: новый пакет, менеджер, воркер, RPC/MCP-сервис, бот, интеграция; цикл, который собирает id, строит map или конвертирует список; фоновая или периодическая задача; фильтр по колонке, неймспейсы.
- **/gold-arch — спека против скилла.** Если спека проекта или соседний сервис расходится со скиллом, агент называет расхождение и спрашивает, а до ответа следует скиллу.
- **/gold-arch — модели домена и бизнес-объекты.** Модели домена встраивают db-модели (`type Task struct{ db.Task }`), из репозитория — сразу `NewX`, правила — методы объекта с именем по смыслу (`t.IsClosed()`, `s.HasAgents()`, `q.CanAnswer(p)`, `t.NeedsReview()`). Экспортируемые методы домена не принимают и не возвращают db-типы, API-слои (`rpc`, `mcp`, бот) не импортируют `pkg/db` — с правилом depguard.
- **/gold-arch — db тонкий.** В ручном db-коде только универсальные примитивы (`WithWhere`, `UpdateBy`, `WithLock`, `WithOrder`, методы Search), без литералов состояний и бизнес-выборок; правила — в `query.go` домена. Раньше атомарный claim целиком разрешался в db.
- **/gold-arch — транзакции, раскладка, конвертеры.** `db.TxManager` в менеджерах вместо `RunInTransaction` в каждом методе; `model.go`/`query.go`/`collection.go` домена, `pkg/mcp`, клиенты в `pkg/client/` (в том числе Telegram Bot API), `pkg/app/cron.go`; поддомены от ~3 тыс. строк; имена конвертеров `NewX`/`newX`/`.ToModel()`/`.ToDB()`; построитель текстов сообщений с автоэкранированием.
- **/mfd — неймспейсы по поддоменам** (2–8 таблиц) и **поля Search прежде `search.With`**: таблица SQL → SearchType, методы Search в `<ns>_ext.go` для того, что генератор не выражает, ловушки `NULL`/`ARRAY`/jsonb. `<Attribute>` в `<ns>.xml` пишет только `mfd-xml`.
- **/cron.** Воркер — метод менеджера, расписание — `pkg/app/cron.go`; без пакета `<domain>/cron` и своего генерика `Job`.
- **/colgen.** Лямбды в `mcp.Map`, второй `MapP` в API-пакете (`-funcpkg=<domain>`), циклы по `[]db.X` в домене; в `pkg/db` colgen не кладётся.
- **/go-review (Cheney).** Major: API импортирует `pkg/db`, db-типы в сигнатурах домена, литералы в ручном db-коде, воркер или клиент не на своём месте. Minor: ручные циклы вместо colgen, конвертер не по имени, `search.With` вместо поля Search.
- **/testing.** Тест create проверяет поля, которые заполняет база; e2e «свой клиент ↔ свой сервер» через `httptest.NewServer` на тестовой БД.
- **/solve.** `/gold-arch` и `/cron` подключаются по контексту; расхождение спеки со скиллом называется в spec; SIMPLIFY не переносит код между слоями вопреки `/gold-arch`.

### Поведение генераторов

- /mfd: `Add<Entity>` не возвращает DEFAULT-колонки (`createdAt`), а с ops пишет в базу `0001-01-01` — обход `WithDefaults`; `ARRAY`-фильтр с пустым срезом не ставится — выборка или `UpdateBy` по всей таблице. Это известное поведение генератора, в скилле — с обходами. Формат флага `-n` у `mfd-generator xml` — `ns:t1,t2` (README пишет `=`, [vmkteam/mfd-generator#73](https://github.com/vmkteam/mfd-generator/issues/73)).
- /rpcgen ≤ v2.5.7: Go-клиент заменяет ошибку сервера sentinel'ом и теряет `message` и `data` ([vmkteam/rpcgen#42](https://github.com/vmkteam/rpcgen/issues/42)) — обход через `http.RoundTripper`.

### Новое

- Evals: `cron-background-worker`, `colgen-manual-loops`, `mfd-search-not-with`, `gold-arch-mcp-domain-models` — срабатывание скиллов по словам задачи без их названия.

## 1.2.0 — 2026-09-29

Скиллы адаптированы под Claude Opus 5 / 5.5, в них перенесён опыт конвейера vmksrv. Изменения проверены набором `claude plugin eval` (`plugins/developer/evals/`).

### Изменения поведения

- **/testing — стиль тестов как в соседних файлах.** Новый тест пишется на том же фреймворке, что соседние `*_test.go` пакета: в пакете на goconvey — на goconvey. В 1.1.0 новые тесты всегда писались на `t.Run` + testify, из-за чего стили в пакете смешивались. В новых пакетах и проектах по-прежнему `t.Run` + testify.
- **/go-review — полнота и калибровка.** Лимит «max 3 blocker, 5 major» снят: ревью сообщает все находки с severity и уверенностью. blocker/major ставится только тому, что реально сработает; для каждой такой находки — блок «инвариант | ломающий вход | как чинить | какой тест». Критерии приёмки проверяются по одному (ACCEPTANCE), одна проблема — одна находка.
- **/solve — plan mode и артефакты.** Research и spec пишутся в файл плана и сохраняются в `docs/llm/tasks/` после утверждения через ExitPlanMode. SIMPLIFY — один проход модели по своему диффу, полный `/simplify` — только для крупных диффов. Повторное ревью смотрит исправленные места. После задачи с провальными раундами уроки записываются в секцию «Уроки» project-index и читаются в начале следующих задач.
- **/solve, /onboard — `.gitignore`.** Игнорируется только `docs/llm/tasks/`, а не весь `docs/llm/`: в некоторых проектах там закоммиченная документация.
- **/commit-msg.** `make fmt lint` запускается, только если в Makefile есть эти цели, и не блокирует сообщение. Subject — до 50 символов без префикса тикета и не длиннее 72 целиком.
- **/investigate.** Работает в основном контексте. В plan mode (вызов из /solve) возвращает отчёт текстом, /solve сохраняет его в `investigation.md`.
- **/onboard, /scaffold, /skills-check** вызываются только вручную.

### Исправления

- /solve: шаблоны находятся через `${CLAUDE_SKILL_DIR}` (раньше путь был относительно проекта пользователя), MR создаётся в `base_branch`, а не в захардкоженный `devel`, JSON комментария в YouTrack собирается через jq (раньше ломался на многострочных артефактах).
- /incident: метрики приведены к `/prometheus`, Loki-запросы — через `| json`, изменения сравниваются с задеплоенным релизом, а не с `HEAD~5`, issue в Sentry закрывается только после подтверждения.
- /security, /zenrpc: `newInternalError(err)` безопасен только при `zm.WithErrorSLog`; `NewStringError(500, ...)` теряет причину ошибки для Sentry.
- /mr-review, /decompose, /youtrack, /gitlab: многострочный текст в JSON — через jq.
- Путь к `project-index.md` одинаковый во всех скиллах.

### Новое

- `plugins/developer/evals/` — кейсы для `claude plugin eval`: /go-review, /commit-msg, /testing, справочники /loki, /pgd, /security, /gold-arch, /zenrpc, выбор /pgmdd вместо /pgd, отсутствие ложных срабатываний.
- `solve/publish-artifacts.sh`, `skills-check/probe.sh` — детерминированные шаги вынесены в скрипты.
- Frontmatter: `argument-hint`, `paths` для /pgd и /pgmdd, `effort`, `allowed-tools: Bash(pcurl:*)` для читающих data-source скиллов.
